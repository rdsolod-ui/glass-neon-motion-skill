# Мудборд как карта решений

Мудборд должен помогать выбрать и воспроизвести решение. Набор ссылок без визуальной структуры и пояснений не заменяет мудборд. Даты проверок относятся к наблюдению, а не к вечной доступности сайта.

## Состав доски

- Две крупные сцены: light frost и dark smoke, с одинаковой иерархией контента для сравнения.
- Материальная полоса: плотный текстовый фон → матовое стекло → прозрачный декоративный слой. Покажи влияние фона, не только hex.
- Палитра с ролями: canvas / text / secondary text / control / focus / decorative cyan / lime / pink. Neon decorative и action text — разные токены.
- Типографика с реальной русской строкой, длинным заголовком, числом и ссылкой; единая семья иконок.
- Карта компонентов, сгруппированная по функции. Поиск и фильтры не должны уничтожать читаемую исходную карту.
- Motion-полоса с replay для примеров: вход, hover/press, переключение, раскрытие, overlay, progress. Кнопки воспроизведения уместны для учебного атласа; в обычном интерфейсе движение вызывается смысловым действием пользователя.

## Карточка референса

Фиксируй поля: точный URL → дата → тип наблюдения → наблюдённый паттерн → собственная адаптация → проверка mobile/accessibility → статус реализации.

Типы наблюдения: `visual screenshot`, `live interaction`, `source/docs only`, `unavailable`. Если проверена только картинка, не приписывай ей easing, scroll или поведение меню. Внешний референс может не быть доступным: перенимай композиционную идею, а дефекты не копируй.

## Права и честность

Ссылка на сайт не даёт лицензию на фотографию, шрифт, логотип или полный дизайн. По умолчанию создавай собственные CSS/SVG-образцы и подписывай «оригинальная интерпретация», рядом оставляй ссылку на вдохновение. Screenshots референсов храни как исследовательские материалы с атрибуцией и не выдавай за собственные assets. Публикация чужих assets требует проверки прав. У кода, демофотографий и Pro-шаблонов могут быть разные условия.

Карта является расширяемой: «все существующие элементы» — не проверяемый предел. Явно назови семьи, покрытые паттерны и исключения: платежная интеграция, auth/backend, сложные rich-text редакторы, native widgets и физическая рефракция не возникают из красивой карточки.
