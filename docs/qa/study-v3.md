## Пробное применение скилла к новому заданию

Сценарий: небольшая форма входа в светлой/тёмной теме с выбранными tabs. План выведен из актуального `skill/glass-neon-motion/SKILL.md`, `references/html-atlas.md` и `references/motion-families.md`:

1. Сохранить HTML/CSS/JS стек. Сделать семантические `form`, постоянные `label`, `input type=email/password`, `autocomplete=username/current-password`, явную submit-кнопку и ошибки с `aria-describedby`. Демоформа не отправляет данные наружу и не сохраняет пароль. Реальная авторизация остаётся отдельной интеграцией.
2. Выбрать 2D film или 3D optical edge для внешней панели, с устойчивым читаемым слоем полей. Light/dark токены независимы; neon action/text и декоративное свечение разделены. У полей разрешена функциональная граница, у стекла нет равномерного декоративного outline; focus не удаляется.
3. Tabs реализовать как составной паттерн: `tablist`, `tab`, `tabpanel`, `aria-selected`, roving tabindex, стрелки/Home/End, корректные связи id и скрытие неактивной панели. Сначала статичная функция и keyboard, затем краткий marker/state transition. В этой небольшой vanilla сборке не устанавливать React/Motion/GSAP ради одного переключателя.
4. Состояния: idle, selected, focus, submitting, invalid, success. Busy не заменяет readonly/disabled; результат и ошибки понятны без движения. Для частой смены tabs достаточно краткого CSS feedback, для редкого success — конечный WAAPI эффект при необходимости. Один владелец анимируемого свойства.
5. Motion-score указывает purpose/trigger/owner/timing/interruption/reduced/cleanup. Повтор прерывает прежнее движение; reduced motion при старте и live сохраняет конечное читаемое состояние без opacity/filter/stagger, если заявлен неподвижный режим. Solid/forced-colors сохраняют смысл.
6. Приёмка: мобильная ширина и длинные данные, две темы, keyboard/touch, no-JS границы демо, реальные ограничения формы, reduced/solid, ошибки ресурсов и scoped cleanup. Native agent discovery и публикация проверяются отдельно от сохранённого навыка.

Результат forward review: **Approve для проверенного документального контракта**. Противоречий, требования исполнять чужие scripts или неподтверждённых обещаний production/readiness не обнаружено. Упоминание all HTML ограничено проверяемым стандартным inventory; custom elements, obsolete/experimental и SVG/MathML не смешаны с числом обычных HTML-тегов. Это архитектурный план, не утверждение о создании/тестировании login-формы.
