## Что исправлено по замечаниям

- Светлая тема + solid fallback: Smoke сохраняет собственную тёмную основу.
- Модальный focus: Tab/Shift+Tab удерживаются, Escape закрывает, focus возвращается; повторное открытие сбрасывает прокрутку.
- Длинный пользовательский ввод: переносится внутри ограниченного preview без горизонтального переполнения.
- Range использует CSS variable; не переопределяет solid/reduced-transparency inline blur.
- Reduced-motion отключает и активные WAAPI effects, и hover/press transforms.
- Экспорт явно обозначен как частичные accent/blur токены, не полный набор темы.
- 48 mini previews получили отдельную форму соответствующего компонента; optical highlight анимирует собственный слой.

## Реальная область проверки

Windows, Node 24.18.0, npm 11.16.0, существующий dedicated Chromium/CDP. Desktop 1440/768 и mobile 390/320; обе темы; touch context; диалоги, меню, форма, CSS download, фильтр/поиск, actual animated intermediate/final states, reduced-motion до загрузки и live. Runtime/network errors в проверенных сценариях не обнаружены.

Проверка fallback/reduced-transparency принудительно активировала соответствующие CSS-ветки в изолированном ответе stylesheet. Это проверка ветвей, не сертификация старого браузера или системной настройки физического устройства. Контраст sampled, не полный WCAG-аудит. Скриншоты просмотрены агентами в перечисленных ими представлениях; root дополнительно просмотрел общий тёмный сайт и светлые формы атласа.

Не проверены Safari, Firefox, физические телефоны, screen reader, слабая GPU, FPS/Core Web Vitals. На сайте нет production backend, оплаты, загрузки файлов или реальной карты. Атлас — 48 схем семейств, не 48 завершённых виджетов.

- `scripts/qa-*.cjs` и `scripts/moodboard-*.cjs` используют отдельные временные browser contexts. Для запуска нужен Playwright (`PLAYWRIGHT_MODULE` указывает на установленный модуль либо обычный `playwright`), уже работающий локальный сайт на 4177 и dedicated CDP на 9223. Они не устанавливают браузер и не запускают пользовательский Chrome.
- `scripts/qa-site-contrast.py` дополнительно требует Pillow и входные screenshots от contrast capture. Это отдельные QA-зависимости, не зависимости сайта.
- Снимки и начальные сырые результаты остаются локально в `qa/`, исключённом из Git. Исходные отчёты могут ссылаться на эти локальные файлы. Скрипты создают новые свидетельства, не исторический результат.

GitHub хранит исходники и компактную приёмку; публичный хостинг демо не входит в факт загрузки репозитория. Для просмотра используется локальный server либо самостоятельная публикация `dist/`.
