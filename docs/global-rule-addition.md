# Glassmorphism / neon / motion — дополнение правил

Использовать `glass-neon-motion` для запрошенных стеклянных сайтов, light/dark систем, неоновых акцентов и glass-мудбордов. Это предметное расширение текущего frontend-процесса, не замена остальных стилей. Прямой brief на glass имеет приоритет над house-style запретами стекла/градиентов; читаемость и QA сохраняются.

Порядок: текущий brief → реальные референсы и карта адаптации → статическая композиция → независимые light/dark токены → типографика/иконки → motion-score → реализация → отдельная приёмка мудборда и сайта. Агентов привлекать при пользовательском разрешении на делегирование.

Использовать tint/edge/depth и ограниченный blur; длинный текст/таблицы/формы размещать на стабильной плоскости. Неон выделяет действие, не заменяет focus или текстовый контраст. Проверять composited contrast поверх крайних фонов, solid fallback, reduced-transparency и forced-colors. CSS blur не объявлять нативным Liquid Glass.

CSS/WAAPI — достаточная базовая сборка; React/Motion/GSAP/headless primitives добавлять только под нужные состояния и сцены, локально с lockfile. Один владелец каждого свойства; конечные эффекты, live reduced-motion, прерывание и cleanup. Не устанавливать все библиотеки и не менять глобальный runtime.

Мудборд различает live-пример, визуальный этюд, рецепт и out-of-scope; список семейств не равен универсальной библиотеке. Источник/наблюдение/адаптация и лицензии отдельно. Проверять desktop/mobile, клавиатуру/touch, длинный ввод, модальный focus, ошибки консоли и фактическое движение. Файлы, установка, discovery, browser QA и публикация — отдельные статусы.
